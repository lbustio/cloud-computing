## Filosofía del módulo

Este módulo se enfoca en el uso de infraestructura cloud y pipelines de observabilidad para resolver tareas reales de monitoreo y análisis de seguridad.

El objetivo NO es construir un SIEM enterprise completo ni profundizar en herramientas ofensivas complejas.

El módulo busca que el estudiante:

- recolecte eventos,
- procese telemetría,
- monitoree infraestructura,
- analice actividad sospechosa,
- visualice eventos,
- y construya mecanismos básicos de detección sobre infraestructura cloud real.

El enfoque será completamente práctico y orientado a análisis técnico.

## Objetivo general del módulo

Que el estudiante sea capaz de utilizar infraestructura cloud, Elasticsearch y Kibana para construir un sistema básico de monitoreo y análisis de eventos de seguridad.

El estudiante deberá comprender:

- telemetría,
- observabilidad,
- monitoreo,
- ingestión de logs,
- correlación básica,
- análisis de eventos,
- y detección simple de actividad sospechosa.

## Continuidad con módulos anteriores

Este módulo reutiliza completamente la infraestructura desplegada durante:

- Módulo 1,
- y Módulo 2.

Las máquinas virtuales, pipelines y dashboards previamente construidos evolucionarán para soportar tareas de monitoreo y análisis de seguridad.

## Justificación del enfoque

El módulo NO se centra en:

- malware avanzado,
- reversing,
- explotación ofensiva,
- pentesting agresivo,
- ni arquitecturas SIEM enterprise complejas.

Las razones son:

- tiempo limitado,
- complejidad excesiva,
- restricciones éticas,
- y necesidad de mantener un enfoque práctico y coherente con el curso.

En su lugar, el módulo se enfoca en tareas reales y ampliamente utilizadas en:

- SOC,
- monitoreo cloud,
- observabilidad,
- análisis de logs,
- threat hunting básico,
- y detección de actividad sospechosa.

## Actividad práctica principal

Cada estudiante deberá construir un sistema básico de monitoreo y análisis de eventos de seguridad utilizando infraestructura cloud desplegada en GCP.

## Infraestructura mínima requerida

Cada estudiante deberá contar con:

- VM Linux en GCP.
- Elasticsearch funcional.
- Kibana funcional.
- Pipeline de ingestión operativo.
- Dataset de eventos.
- Dashboard de monitoreo.
- Recolección de logs.

## Actividades técnicas sugeridas

### Actividad 1. Recolección de logs

Objetivos:

- identificar fuentes de eventos,
- extraer logs,
- procesar registros,
- preparar datasets.

Fuentes posibles:

- auth.log,
- nginx,
- apache,
- syslog,
- eventos SSH.

### Actividad 2. Centralización de eventos

Objetivos:

- enviar eventos a Elasticsearch,
- validar indexación,
- verificar consistencia,
- explorar eventos.

### Actividad 3. Construcción de dashboards

Objetivos:

- visualizar actividad,
- identificar patrones,
- monitorear eventos,
- construir métricas.

Ejemplos:

- intentos de login,
- IPs más activas,
- accesos fallidos,
- eventos por hora,
- actividad temporal.

### Actividad 4. Análisis de eventos sospechosos

Objetivos:

- identificar patrones anómalos,
- detectar actividad repetitiva,
- buscar eventos sospechosos,
- documentar hallazgos.

### Actividad 5. Simulación simple de eventos

Opciones posibles:

- intentos fallidos SSH,
- generación controlada de logs,
- accesos repetitivos,
- tráfico básico.

Las simulaciones deben mantenerse en entornos controlados y académicos.
