# Clase práctica: Infraestructura Cloud en GCP

## Propósito de la sesión

Esta sesión está destinada a desarrollar, completar y corregir la práctica asignada en la sesión anterior. No se trata de introducir una actividad nueva, sino de usar el tiempo de clase para que cada estudiante avance de forma controlada en la creación de una infraestructura básica en Google Cloud Platform.

Durante la sesión, cada estudiante deberá crear o terminar de configurar una máquina virtual Linux en GCP, conectarse por SSH, instalar software básico, publicar un servidor web mínimo con Nginx, verificar su funcionamiento desde Internet y documentar el proceso en un reporte técnico.

El objetivo central es que el estudiante no entregue solamente capturas aisladas, sino que pueda explicar qué hizo, por qué lo hizo, qué problemas encontró, cómo los resolvió y qué riesgos técnicos o económicos identificó.

## Relación con la sesión anterior

La sesión anterior presentó los elementos básicos de Google Cloud Platform y dejó como práctica la creación de infraestructura básica en la nube. Esta clase práctica retoma esa tarea y la convierte en una sesión de trabajo supervisado.

La actividad se concentra en:

- crear o revisar un proyecto en GCP;
- crear una máquina virtual Linux en Compute Engine;
- seleccionar región, zona, tipo de máquina y disco;
- configurar acceso remoto por SSH;
- habilitar tráfico HTTP;
- instalar Nginx, `htop` y `mc`;
- verificar conectividad local y pública;
- documentar evidencias técnicas;
- analizar costos, riesgos y problemas encontrados;
- detener o eliminar recursos al finalizar.

## Resultado esperado

Al terminar la sesión, cada estudiante deberá contar con:

1. Una máquina virtual Linux creada en Google Cloud Platform.
2. Acceso SSH funcional a la máquina virtual.
3. Nginx instalado y activo.
4. La página inicial de Nginx visible desde un navegador usando la IP pública de la VM.
5. `htop` y `mc` instalados y ejecutados al menos una vez.
6. Evidencias suficientes para construir el reporte.
7. Una bitácora breve de problemas encontrados y soluciones aplicadas.
8. La VM detenida o eliminada si ya no se utilizará.

## Organización de la clase

### 1. Revisión inicial

Cada estudiante debe verificar si ya cuenta con:

- acceso a su cuenta de GCP;
- proyecto creado o seleccionado;
- facturación habilitada si GCP lo solicita;
- acceso a Compute Engine;
- VM creada o lista para crearse;
- notas de avance de la tarea anterior.

Si algún estudiante no pudo iniciar la tarea, debe comenzar desde la creación del proyecto y la VM.

### 2. Creación o revisión de la VM

Los estudiantes que ya tengan la VM creada deberán revisar:

- nombre de la instancia;
- sistema operativo;
- región y zona;
- tipo de máquina;
- disco persistente;
- IP pública;
- reglas de firewall;
- estado de la instancia.

Los estudiantes que aún no tengan la VM deberán crearla siguiendo los requisitos de la tarea.

### 3. Conexión SSH

Cada estudiante debe conectarse a la VM mediante SSH desde la consola de GCP.

Al entrar a la máquina, se recomienda ejecutar:

```bash
hostname
whoami
uname -a
cat /etc/os-release
free -h
df -h
```

Estas salidas sirven como evidencia de acceso, sistema operativo, memoria y disco.

### 4. Instalación de software

Dentro de la VM, se deben instalar los paquetes obligatorios:

```bash
sudo apt update
sudo apt install -y nginx htop mc
```

Después de la instalación, se debe verificar el estado de Nginx:

```bash
systemctl status nginx
```

También se puede usar:

```bash
sudo systemctl is-active nginx
```

El resultado esperado es que el servicio aparezca como activo.

### 5. Verificación local de Nginx

Desde la propia VM:

```bash
curl http://localhost
```

Si Nginx está funcionando, la terminal debe mostrar el contenido HTML de la página inicial.

### 6. Verificación desde navegador externo

Cada estudiante debe copiar la IP pública de su VM y abrirla en un navegador:

```text
http://DIRECCION_IP_PUBLICA
```

La evidencia debe mostrar la página inicial de Nginx cargando desde Internet.

Si la página no responde, se deben revisar:

- estado de la VM;
- IP pública correcta;
- regla de firewall para HTTP;
- casilla de permitir tráfico HTTP;
- estado del servicio Nginx;
- errores de red del navegador.

### 7. Verificación de herramientas adicionales

Ejecutar:

```bash
htop
```

Tomar evidencia de la interfaz de monitoreo. Para salir, usar `F10` o `q`.

Ejecutar:

```bash
mc
```

Tomar evidencia del administrador de archivos en terminal. Para salir, usar `F10`.

## Guía de troubleshooting

Durante la clase se espera que aparezcan errores. El objetivo no es evitarlos, sino aprender a diagnosticarlos.

### No puedo conectarme por SSH

Revisar:

- que la VM esté encendida;
- que la cuenta de GCP tenga permisos suficientes;
- que no haya errores temporales en la consola;
- que el navegador permita ventanas emergentes si se usa SSH desde GCP;
- que la regla de firewall para SSH no haya sido modificada de forma incorrecta.

### Nginx no instala

Probar:

```bash
sudo apt update
sudo apt install -y nginx
```

Si hay errores, documentar:

- mensaje exacto;
- comando ejecutado;
- solución intentada;
- resultado final.

### Nginx instala pero no responde

Revisar:

```bash
sudo systemctl status nginx
sudo systemctl restart nginx
curl http://localhost
```

Si responde localmente pero no desde navegador, el problema probablemente está en firewall, IP pública o regla HTTP.

### La página no abre desde Internet

Revisar en GCP:

- que la VM tenga IP pública;
- que la URL use `http://` y no `https://`;
- que el puerto 80 esté permitido;
- que la regla de firewall aplique a la instancia correcta;
- que Nginx esté activo.

### Aparecen costos inesperados

Revisar:

- tipo de máquina seleccionado;
- región;
- disco;
- recursos activos;
- advertencias del estimador de costos;
- si la VM quedó encendida después de la práctica.

Al finalizar, detener o eliminar la VM si ya no se utilizará.
