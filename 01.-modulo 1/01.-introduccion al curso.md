## 1. Enfoque general del curso

Se explico que el curso tendra un enfoque eminentemente practico. Debido a la amplitud y naturaleza dinamica de los temas abordados, no se seguira un esquema tradicional basado en clases expositivas y examenes teoricos.

El curso se centrara en:

- aprendizaje practico,
- experimentacion,
- resolucion de problemas,
- investigacion autonoma,
- y documentacion tecnica.

El objetivo es que cada estudiante construya progresivamente una infraestructura funcional en la nube sobre la cual se desarrollaran todas las actividades del curso. Por esa razon, cada practica debe entenderse como parte de una infraestructura que ira creciendo modulo por modulo, no como un ejercicio aislado.

## 2. Estructura general del curso

Se presento la organizacion del curso en cinco modulos:

1. Fundamentos de computacion en la nube e infraestructura cloud.
2. Pipelines distribuidos, observabilidad y analisis de eventos.
3. Telemetria, monitoreo y analisis de seguridad en infraestructura cloud.
4. Inteligencia artificial y aprendizaje automatico aplicados a telemetria y eventos de seguridad.
5. Blockchain y tecnologias descentralizadas.

Cada modulo se construye sobre la infraestructura y los resultados obtenidos en los modulos anteriores. En consecuencia, la primera maquina virtual, las configuraciones iniciales y la documentacion tecnica de esta sesion seran la base para actividades posteriores.

## 3. Plataforma tecnologica

Todo el curso utilizara Google Cloud Platform (GCP) como plataforma principal.

La seleccion de GCP se realizo por las siguientes razones:

- disponibilidad de creditos gratuitos para nuevos usuarios,
- amplio conjunto de servicios administrados,
- integracion nativa con herramientas de analitica e inteligencia artificial,
- documentacion abundante,
- y una interfaz relativamente amigable para usuarios principiantes.

El uso de GCP tambien permite trabajar desde el inicio con infraestructura real: maquinas virtuales, redes, reglas de firewall, almacenamiento y servicios accesibles desde Internet.

## 7. Conceptos minimos antes de la practica

Antes de iniciar el despliegue, es importante ubicar algunos conceptos basicos. No se busca memorizarlos de forma teorica, sino reconocerlos durante la practica.

### Computacion en la nube

La computacion en la nube permite usar recursos de computo, almacenamiento, red y servicios administrados sin comprar ni operar infraestructura fisica propia. En lugar de instalar servidores locales, se crean recursos bajo demanda en plataformas como Google Cloud Platform.

### Caracteristicas esenciales del modelo cloud

Durante la practica se observaran varias caracteristicas del modelo cloud:

- aprovisionamiento bajo demanda,
- acceso por red,
- elasticidad,
- pago por consumo,
- administracion remota,
- y uso de infraestructura distribuida.

### Modelos de servicio: IaaS, PaaS y SaaS

Los modelos de servicio ayudan a distinguir que parte de la infraestructura administra el proveedor y que parte administra el usuario.

- IaaS: el proveedor entrega infraestructura virtual, como maquinas virtuales, redes y discos. Google Compute Engine pertenece a este modelo.
- PaaS: el proveedor ofrece una plataforma para desplegar aplicaciones sin administrar directamente servidores.
- SaaS: el usuario consume una aplicacion completa, como correo, almacenamiento colaborativo o sistemas web ya terminados.

En esta sesion se trabajara principalmente con IaaS, porque el equipo administrara una VM Linux, instalara software y configurara acceso de red.

### Modelos de despliegue

Los modelos de despliegue describen donde se ejecuta la infraestructura y quien la controla.

- Nube publica: infraestructura operada por un proveedor cloud y consumida por usuarios u organizaciones. GCP, AWS y Azure son ejemplos de nube publica.
- Nube privada: infraestructura cloud usada por una sola organizacion, normalmente con mayor control interno.
- Nube hibrida: combinacion de infraestructura local o privada con servicios de nube publica.
- Multi-cloud: uso de servicios de mas de un proveedor cloud.

En esta sesion se usara nube publica mediante GCP. Aun asi, es importante reconocer que la eleccion del modelo de despliegue afecta costos, control, seguridad, cumplimiento normativo y dependencia de proveedor.

### Proyecto en GCP

Un proyecto en Google Cloud Platform agrupa recursos, permisos, facturacion, APIs y configuraciones. Para el curso, el proyecto funciona como el espacio de trabajo donde se crearan la maquina virtual, reglas de firewall y recursos posteriores.

### Compute Engine

Compute Engine es el servicio de GCP que permite crear y administrar maquinas virtuales. En esta sesion se usara para desplegar una instancia Debian 12, conectarse por SSH e instalar Nginx.

### Maquina virtual

Una maquina virtual es un servidor creado sobre infraestructura cloud. En esta practica se usara una VM Debian para instalar software, ejecutar comandos por SSH y publicar un servicio web basico.

### Region y zona

Una region representa una ubicacion geografica de infraestructura cloud. Una zona es una ubicacion especifica dentro de una region. La region y zona influyen en disponibilidad, latencia y costo. Por eso, el equipo debe documentar que region y zona eligio para su VM.

### VPC, firewall e IP publica

La VPC es la red virtual donde se conectan los recursos cloud. Las reglas de firewall controlan que trafico puede entrar o salir. La IP publica permite acceder a la VM desde Internet. En esta actividad se abrira solamente el puerto `80` para probar HTTP.

La direccion IP privada permite comunicacion interna dentro de la red cloud. La direccion IP publica permite comunicacion desde Internet. Para verificar el sitio web se usara la IP publica de la VM.

### Servicio web

Un servicio web es una aplicacion o servidor que responde solicitudes desde un navegador. En esta practica se usara Nginx para comprobar que la VM puede publicar contenido hacia Internet.

### Bucket de almacenamiento

Un bucket es un contenedor de almacenamiento de objetos en Google Cloud Storage. Sirve para guardar archivos, evidencias, datasets, respaldos o contenido estatico. A diferencia del disco de la VM, un bucket no depende de una maquina virtual especifica y puede ser usado por otros servicios cloud.

En esta sesion se creara un bucket sencillo para comprender el almacenamiento cloud basico y documentar su relacion con la arquitectura desplegada.

## 8. Costos, riesgos y troubleshooting

La practica no termina cuando la VM enciende. Tambien hay que revisar costo, exposicion a Internet y posibles fallas de configuracion.

### Costos y billing

Cada equipo debe revisar el estimado de costo mostrado por la consola de GCP antes de crear la VM. Tambien debe identificar donde se consulta el panel de Billing del proyecto.

Recomendaciones:

1. Verificar el costo estimado antes de crear recursos.
2. Detener o eliminar recursos que no se esten usando.
3. Revisar si existen alertas de presupuesto disponibles.
4. Documentar el costo aproximado de la configuracion utilizada.

### Buenas practicas para reducir costos

El control de costos es parte del trabajo tecnico en cloud. Una configuracion pequena puede parecer barata por hora, pero si permanece encendida todo el mes puede generar cargos acumulados.

Buenas practicas recomendadas:

1. Apagar la VM cuando no se este usando.
   - Al detener la VM se deja de cobrar el uso de CPU y memoria.
   - El disco persistente sigue existiendo y puede seguir generando costo.
2. Eliminar recursos que ya no se necesitan.
   - Si la VM ya no se usara, eliminarla evita cargos futuros.
   - Antes de eliminarla, revisar si se necesita conservar evidencia o archivos.
3. Revisar discos persistentes despues de borrar una VM.
   - En algunos casos el disco puede quedar separado de la instancia.
   - Un disco persistente sin VM tambien puede generar costo.
4. Evitar IPs estaticas innecesarias.
   - Una IP externa estatica reservada y sin uso puede generar cargos.
   - Para esta practica basta con usar la IP publica efimera asignada a la VM.
5. No sobredimensionar la instancia.
   - Usar maquinas pequenas para pruebas iniciales.
   - Aumentar recursos solo cuando exista una razon tecnica clara.
6. Revisar Billing periodicamente.
   - Consultar el panel de facturacion durante el curso.
   - Documentar cualquier cambio inesperado en el costo.

Apagar la VM ayuda a reducir costos porque detiene el cobro de computo, pero no elimina todos los costos asociados. Para dejar de pagar por completo un recurso, normalmente es necesario eliminar tambien los recursos persistentes asociados que ya no se utilizaran.

### Riesgos de seguridad basicos

Abrir un puerto hacia `0.0.0.0/0` significa permitir trafico desde cualquier origen de Internet. En esta practica se hace de forma controlada para publicar un servidor web basico, pero debe entenderse como una exposicion real.

Puntos minimos a cuidar:

- abrir solo los puertos necesarios,
- no publicar credenciales, llaves privadas o tokens,
- usar SSH solamente desde los mecanismos autorizados,
- recordar que HTTP no cifra el trafico,
- documentar cualquier regla de firewall creada.

### Normativas y compliance

En esta sesion no se realizara un analisis juridico, pero si se debe entender que las decisiones tecnicas en cloud pueden tener implicaciones de privacidad, proteccion de datos y cumplimiento normativo.

Referencias minimas:

- GDPR: marco europeo de proteccion de datos personales. Es relevante cuando se almacenan, procesan o transfieren datos personales.
- ISO/IEC 27017: guia de controles de seguridad para servicios cloud.
- ISO/IEC 27018: guia orientada a proteccion de informacion personal identificable en nubes publicas.

Para esta practica, el criterio minimo es no subir datos personales, credenciales, llaves privadas, tokens o informacion sensible a la VM, al servicio web o al bucket. Toda evidencia debe ser tecnica y no debe exponer informacion privada.

### Troubleshooting esperado

Si algo falla, el problema tambien forma parte del aprendizaje. Antes de pedir ayuda, el equipo debe revisar:

- si la VM esta en estado `Running`,
- si se puede entrar por SSH,
- si Nginx esta activo,
- si `curl http://localhost` responde dentro de la VM,
- si la regla de firewall permite `tcp:80`,
- si la etiqueta `http-server` esta asociada a la VM,
- si se esta usando la IP publica correcta,
- si el bucket fue creado en el proyecto correcto,
- si los permisos del bucket permiten la operacion que se intenta realizar.

### Almacenamiento cloud

El temario del modulo contempla almacenamiento cloud mediante buckets. En esta sesion se agregara una practica minima de Cloud Storage para que la infraestructura base incluya computo, red, firewall, acceso web y almacenamiento.

El bucket no debe configurarse como publico salvo que el profesor lo indique. Para esta practica basta con crear el bucket, subir un archivo de prueba y documentar su existencia.

### 9.2 Especificaciones de la maquina virtual en Google Cloud Platform (GCP)

Cada estudiante debera crear una maquina virtual (VM) en Google Cloud Platform con las siguientes caracteristicas minimas.

| Recurso | Especificacion |
|--------|----------------|
| Sistema operativo | Debian GNU/Linux 12 (Bookworm) |
| Tipo de maquina | `e2-small` |
| CPU virtuales | 2 vCPU |
| Memoria RAM | 1 GB |
| Disco persistente | 10 GB |
| Tipo de disco | Standard Persistent Disk |
| Arquitectura | x86_64 (64 bits) |
| Nombre de la instancia | `course` |
| Usuario sugerido | `curso` |

#### Justificacion de la configuracion

La maquina de referencia utilizada en el curso tiene las siguientes caracteristicas minimas:

- Sistema operativo: Debian GNU/Linux 12 (Bookworm)
- CPU: 2 vCPU
- Memoria RAM: 969 MiB
- Disco: 10 GB
- Plataforma: Google Compute Engine

Estos valores permiten trabajar con una instancia pequena, suficiente para instalar un servidor web basico y realizar pruebas iniciales sin consumir recursos innecesarios.

Un criterio importante para escoger esta configuracion es el costo. De acuerdo con la pagina oficial de precios de Compute Engine de Google Cloud, una instancia `e2-small` Linux en la region `us-central1` tiene un costo aproximado de `0.016752855 USD` por hora. Si la maquina permaneciera encendida todo el mes, usando una referencia de 730 horas mensuales, el costo aproximado de computo seria:

```text
0.016752855 USD/hora x 730 horas = 12.23 USD/mes
```

A esto debe sumarse el disco persistente. Para un disco estandar de 10 GB, usando la referencia oficial de `0.04 USD` por GB/mes en regiones de Estados Unidos, el costo aproximado adicional seria:

```text
10 GB x 0.04 USD/GB-mes = 0.40 USD/mes
```

Por lo tanto, una VM con esta configuracion tendria un costo mensual aproximado de `12.63 USD` si se mantiene encendida de forma continua durante todo el mes. Este valor puede variar segun la region, el tipo exacto de disco, el trafico de red, impuestos, creditos disponibles y cambios en la lista oficial de precios, por lo que siempre debe verificarse el estimado mostrado por la consola de GCP antes de crear la instancia.

Fuentes de referencia:

- [Precios de Compute Engine](https://cloud.google.com/compute/all-pricing)
- [Precios de discos e imagenes de Compute Engine](https://cloud.google.com/compute/disks-image-pricing)

### 9.4 Conexion a la VM por SSH

Antes de ejecutar comandos dentro de la maquina virtual, es necesario conectarse por SSH.

Opcion desde la consola de GCP:

1. Ir a `Compute Engine > VM instances`.
2. Ubicar la instancia `course`.
3. Verificar que la instancia este en estado `Running`.
4. Presionar el boton `SSH`.
5. Esperar a que se abra la terminal web conectada a la VM.

Opcion desde Google Cloud CLI:

```bash
gcloud compute ssh lbustio@course --zone ZONA_DE_LA_VM --project ID_DEL_PROYECTO
```

Sustituye `ZONA_DE_LA_VM` por la zona donde fue creada la instancia e `ID_DEL_PROYECTO` por el identificador del proyecto en GCP.

Una vez dentro de la terminal de la VM, ya se pueden ejecutar comandos de verificacion, instalacion y configuracion.

### 9.5 Verificacion inicial de la VM

Una vez conectado por SSH a la VM, ejecutar:

```bash
free -h
lscpu
df -h
cat /etc/os-release
hostnamectl
uname -a
```

Estos comandos permiten comprobar que la maquina creada coincide con las especificaciones solicitadas y que el sistema operativo esta funcionando correctamente.

### 9.6 Inspeccion de VM en GCP

Antes de instalar el servidor web, inspecciona la infraestructura de la maquina virtual. Esto permite documentar el estado inicial de la VM y confirmar sus caracteristicas de sistema operativo, CPU, memoria y disco.

#### Comandos para sistema operativo

| Comando | Funcion |
|---------|---------|
| `cat /etc/os-release` | Muestra distribucion, version e ID del SO (ej. Debian GNU/Linux 12). |
| `lsb_release -a` | Detalles completos del SO (si el paquete esta instalado). |
| `hostnamectl` | Nombre del SO, version del kernel y arquitectura. |
| `uname -a` | Informacion basica del kernel Linux. |

#### Comandos para hardware

| Comando | Funcion |
|---------|---------|
| `free -h` | Memoria RAM total, usada y libre (en GB). |
| `lscpu` | Detalles de la CPU: modelo, nucleos, velocidad. |
| `cat /proc/cpuinfo \| grep "model name" \| head -1` | Solo el nombre del procesador. |
| `df -h` | Espacio en disco usado/libre por filesystem. |
| `lsblk` | Discos fisicos, particiones y tamanos. |

#### Herramientas complementarias

Instala `htop` y `mc` como herramientas de apoyo para inspeccionar y administrar la VM desde la terminal.

`htop` permite observar de forma interactiva el uso de CPU, memoria, procesos activos y carga general del sistema. Es util para confirmar que la VM tiene recursos suficientes y para detectar procesos que consumen demasiada memoria o CPU.

`mc` (Midnight Commander) es un administrador de archivos en modo texto. Permite navegar directorios, copiar, mover, eliminar y revisar archivos desde una interfaz mas comoda que usar solamente comandos como `ls`, `cp`, `mv` o `rm`. Es especialmente util para estudiantes que apenas se familiarizan con la terminal Linux.

```bash
sudo apt update && sudo apt install htop mc -y
```

Documenta los resultados obtenidos como parte del reporte tecnico de la actividad.

### 9.7 Configuracion de firewall HTTP

Para que el servidor web pueda consultarse desde el navegador, se debe permitir trafico HTTP hacia la maquina virtual.

En esta practica se utilizara unicamente HTTP. Esto es suficiente para aprender a crear y administrar una instancia en GCP, conectarse por SSH, instalar software, configurar un servidor web basico y verificar acceso desde fuera de la nube.

HTTPS no funciona automaticamente solo por activar `Allow HTTPS traffic`. Esa opcion, o una regla equivalente de firewall, solamente abre el puerto `443`. Para que HTTPS funcione correctamente tambien se requiere un nombre de dominio, un certificado TLS valido y configuracion adicional de Nginx. Como en esta practica se accedera mediante la IP publica de la VM, se usara HTTP.

Si durante la creacion de la VM no se activo `Allow HTTP traffic`, se puede configurar despues mediante una regla de firewall.

#### Configuracion despues de creada la VM

1. Ir a `Compute Engine > VM instances`.
2. Abrir los detalles de la instancia `course` y seleccionar `edit`.
3. Revisar la seccion `Network tags`.
4. Agregar etiquetas de red, por ejemplo:
   - `http-server`
5. Ir a `VPC network > Firewall`.
6. Crear una regla para HTTP con estos valores:
   - Direction of traffic: `Ingress`
   - Action on match: `Allow`
   - Targets: `Specified target tags`
   - Target tags: `http-server`
   - Source IPv4 ranges: `0.0.0.0/0`
   - Protocols and ports: `tcp:80`

La regla HTTP es necesaria para probar Nginx desde el navegador usando:

```text
http://IP_PUBLICA
```

La configuracion debe documentarse con capturas o evidencia tecnica que muestre la regla aplicada y la etiqueta asociada a la VM.

### 9.8 Instalacion de servidor web

Tras conectarte por SSH a la VM, instala Nginx.

Comandos de instalacion:

```bash
sudo apt update
sudo apt install nginx -y
sudo systemctl status nginx
```

El equipo debe documentar que Nginx quedo instalado y que el servicio se encuentra activo.

Para verificar primero desde la propia VM que el servidor esta respondiendo, ejecuta:

```bash
curl http://localhost
```

Si la instalacion fue correcta, el comando debe regresar el HTML de la pagina inicial de Nginx.

Para verificar desde fuera de GCP, usa la IP publica externa de la VM. Esta prueba debe hacerse desde un navegador en la computadora local del estudiante, no desde la terminal SSH de la VM:

```text
http://IP_PUBLICA
```

Tambien puede verificarse desde una terminal local, fuera de GCP:

```bash
curl http://IP_PUBLICA
```

Si la pagina no carga desde fuera de GCP, pero si responde con `curl http://localhost` dentro de la VM, el problema probablemente esta en la regla de firewall, la etiqueta de red o la IP publica utilizada.

### 9.9 Verificacion de acceso web desde navegador

Una vez instalado el servidor web y configurada la regla de firewall HTTP:

1. Identificar la IP publica externa de la VM.
2. Abrir un navegador web.
3. Ingresar a `http://IP_PUBLICA`.
4. Verificar que aparece la pagina inicial de Nginx.
5. Guardar evidencia del acceso exitoso.

### 9.10 Creacion de bucket en Cloud Storage

Despues de verificar el servidor web, crea un bucket en Google Cloud Storage para completar la infraestructura minima del modulo.

#### Procedimiento desde la consola de GCP

1. Ir a `Cloud Storage > Buckets`.
2. Seleccionar `Create`.
3. Asignar un nombre unico al bucket. El nombre debe ser globalmente unico.
4. Seleccionar una region o ubicacion compatible con la practica.
5. Mantener permisos privados por defecto.
6. Crear el bucket.
7. Subir un archivo de prueba, por ejemplo un archivo `.txt` con el nombre del equipo y la fecha.
8. Verificar que el archivo aparece dentro del bucket.

#### Recomendaciones

- No subir credenciales, llaves privadas, tokens ni datos personales.
- No hacer publico el bucket salvo que exista una instruccion explicita.
- Documentar nombre del bucket, region, archivo subido y configuracion de permisos.
- Si se elimina el bucket al terminar la practica, documentar tambien esa decision.

#### Verificacion opcional con Google Cloud CLI

Si el equipo tiene Google Cloud CLI configurado, puede listar buckets con:

```bash
gcloud storage buckets list --project ID_DEL_PROYECTO
```

Y listar archivos del bucket con:

```bash
gcloud storage ls gs://NOMBRE_DEL_BUCKET
```
